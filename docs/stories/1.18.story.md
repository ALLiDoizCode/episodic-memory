# Story 1.18: Auto-Publish Recommendations

**Status:** Done
**Epic:** 1 - Decentralized Cross-Device & Multi-Agent Memory

**Story Statement:**
**As a** user completing a valuable conversation
**I want** episodic-memory to suggest publishing as skill automatically
**So that** I don't miss opportunities to share knowledge

## Acceptance Criteria

1. After conversation ends (session-end hook), analyze for skill-worthiness:
   - **High tool usage:** >10 tool calls (complex solution)
   - **Code generation:** >100 lines of code written
   - **User signal:** User said "remember this" or "save this pattern"
   - **Problem-solution:** User asked question → Agent solved → User confirmed success
2. If skill-worthy, prompt user: "Publish this conversation as skill? [y/N]"
3. If yes, launch `publish-skill` wizard (Story 1.17)
4. If no, track decision (don't re-prompt for same conversation)
5. Option to disable auto-suggestions: `episodic-memory config set auto-suggest-publish false`

## Integration Verification

- IV1: Complex conversation (>10 tools) triggers suggestion
- IV2: User accepts suggestion → skill published successfully
- IV3: User declines suggestion → not prompted again for that conversation
- IV4: Disabled auto-suggest → no prompts appear

## Dependencies

- Story 1.17 (publish-skill command exists)

## Dev Notes

### Story Context

**Story 1.18 Position in Epic:**

This story completes the **conversation-to-skill publishing workflow** by adding automatic skill-worthiness detection and suggestion prompts. Story 1.17 provided the manual `publish-skill` command; Story 1.18 makes publishing frictionless by proactively suggesting it when appropriate.

**Previous Story Insights:**

Story 1.17 implemented the core publishing workflow using Claude Agent SDK to call `mcp__permamind__publish_skill`. The key learnings:

1. **CLI-only workflow works well**: Using Claude Agent SDK to call MCP tools avoids server-to-server communication complexity
2. **Skill generation heuristics are effective**: Auto-tagging from code blocks, tool usage, and conversation structure produces high-quality skills
3. **Interactive wizard UX is important**: Users need to review/edit suggestions before publishing

**Architectural Approach for Story 1.18:**

Story 1.18 extends the session-end hook workflow (currently runs `episodic-memory sync`) to:

1. **Analyze last conversation** using heuristics (tool count, code lines, user signals)
2. **Prompt user interactively** if conversation is skill-worthy
3. **Launch publish-skill wizard** if user accepts
4. **Track decision** to avoid re-prompting

**Key Design Decision:**

- **Non-blocking**: Suggestion shown AFTER sync completes (don't slow down session-end)
- **Opt-in by default**: Auto-suggest enabled by default, but easily disabled via config
- **Smart throttling**: Only suggest once per conversation (track in `suggested_skills` table)

**NEW Data Model for Story 1.18:**

The `suggested_skills` table tracks auto-suggestion decisions:

```sql
CREATE TABLE IF NOT EXISTS suggested_skills (
  conversation_id TEXT PRIMARY KEY,
  suggested_at INTEGER NOT NULL,
  user_action TEXT,              -- 'accepted', 'declined', 'dismissed'
  skill_id TEXT,                 -- Arweave transaction ID (if published)

  FOREIGN KEY (conversation_id) REFERENCES exchanges(id) ON DELETE CASCADE
);
```

**Fields:**
- `conversation_id`: Unique conversation identifier (prevents duplicate suggestions)
- `suggested_at`: Unix timestamp of suggestion display
- `user_action`: Tracks user's decision (accepted → launches wizard, declined → never prompt again)
- `skill_id`: If accepted, stores resulting skill transaction ID (for analytics)

**Indexes:**
- Primary key on `conversation_id` ensures one suggestion per conversation
- Foreign key cascades deletes (if conversation deleted, suggestion record also deleted)

### Skill-Worthiness Heuristics

[Source: Epic 1 Story 1.18 AC1]

**Heuristic 1: High Tool Usage (>10 tool calls)**

Rationale: Complex problem-solving typically involves extensive tool usage. A conversation with >10 tool calls demonstrates a non-trivial solution.

**Implementation:**

```typescript
function hasHighToolUsage(exchanges: ConversationExchange[]): boolean {
  const totalToolCalls = exchanges.reduce((count, ex) =>
    count + (ex.toolCalls?.length || 0), 0
  );
  return totalToolCalls > 10;
}
```

**Heuristic 2: Code Generation (>100 lines)**

Rationale: Substantial code generation indicates a solution worth capturing. Count lines in code blocks from assistant messages.

**Implementation:**

```typescript
function hasSubstantialCodeGeneration(exchanges: ConversationExchange[]): boolean {
  const codeLineCount = exchanges.reduce((count, ex) => {
    const codeBlocks = ex.assistantMessage.match(/```[\s\S]*?```/g) || [];
    const linesInBlocks = codeBlocks
      .map(block => block.split('\n').length - 2)  // Exclude ``` lines
      .reduce((sum, lines) => sum + lines, 0);
    return count + linesInBlocks;
  }, 0);
  return codeLineCount > 100;
}
```

**Heuristic 3: User Signal ("remember this", "save this pattern")**

Rationale: Explicit user intent to preserve knowledge is strongest signal.

**Implementation:**

```typescript
function hasUserSignal(exchanges: ConversationExchange[]): boolean {
  const signals = [
    'remember this',
    'save this pattern',
    'remember that',
    'keep this',
    'note this down',
    'save this solution'
  ];

  return exchanges.some(ex => {
    const userMsgLower = ex.userMessage.toLowerCase();
    return signals.some(signal => userMsgLower.includes(signal));
  });
}
```

**Heuristic 4: Problem-Solution Pattern**

Rationale: Clear Q&A structure indicates reusable knowledge. Detect question → multi-step solution → confirmation.

**Implementation:**

```typescript
function hasProblemSolutionPattern(exchanges: ConversationExchange[]): boolean {
  if (exchanges.length < 3) return false;

  const firstMessage = exchanges[0].userMessage.toLowerCase();
  const hasQuestion = firstMessage.includes('?') ||
                      firstMessage.match(/^(how|why|what|when|where|can|should)/);

  const hasConfirmation = exchanges.slice(-2).some(ex =>
    ex.userMessage.toLowerCase().match(/thanks|thank you|worked|success|perfect|great/)
  );

  return hasQuestion && hasConfirmation;
}
```

**Combined Heuristic:**

A conversation is skill-worthy if it meets **any 2+ heuristics** or **heuristic 3 (user signal) alone**:

```typescript
function isSkillWorthy(exchanges: ConversationExchange[]): boolean {
  const heuristics = [
    hasHighToolUsage(exchanges),
    hasSubstantialCodeGeneration(exchanges),
    hasUserSignal(exchanges),
    hasProblemSolutionPattern(exchanges)
  ];

  const matchCount = heuristics.filter(h => h).length;

  // User signal alone is sufficient (heuristic 3)
  if (hasUserSignal(exchanges)) return true;

  // Otherwise require 2+ heuristics
  return matchCount >= 2;
}
```

**NEW CLI Command: `suggest-publish`**

This command:
1. Queries database for last conversation (by timestamp)
2. Loads all exchanges for that conversation
3. Analyzes using skill-worthiness heuristics
4. If skill-worthy AND not already suggested, prompts user
5. If user accepts, launches `publish-skill` wizard

**Implementation Pattern:**

```typescript
// src/suggest-publish-cli.ts
export async function suggestPublishCommand(options: SuggestOptions): Promise<void> {
  // 1. Check config for auto-suggest enabled
  const config = await loadConfig();
  if (!config.autoSuggestPublish) {
    console.log('Auto-suggest disabled. Enable with: episodic-memory config set auto-suggest-publish true');
    return;
  }

  // 2. Load last conversation from database
  const lastConversation = await getLastConversation();
  if (!lastConversation) {
    console.log('No conversations found.');
    return;
  }

  // 3. Check if already suggested
  const alreadySuggested = await hasBeenSuggested(lastConversation.id);
  if (alreadySuggested) {
    return;  // Silent exit - don't re-prompt
  }

  // 4. Analyze skill-worthiness
  const exchanges = await loadConversationExchanges(lastConversation.id);
  if (!isSkillWorthy(exchanges)) {
    return;  // Not worthy, silent exit
  }

  // 5. Prompt user
  const shouldPublish = await confirm({
    message: 'This conversation looks valuable! Publish as skill to Permamind?',
    default: false
  });

  // 6. Track decision
  await recordSuggestion(lastConversation.id, shouldPublish ? 'accepted' : 'declined');

  // 7. If accepted, launch publish-skill wizard
  if (shouldPublish) {
    await publishSkillCommand(lastConversation.id, { interactive: true });
  } else {
    console.log('Suggestion declined. You can manually publish later with: episodic-memory publish-skill <conversation-id>');
  }
}
```

### Heuristic Tuning Strategy

**Balancing False Positives vs False Negatives:**

- **False Positive:** Suggesting non-valuable conversation (annoys user)
- **False Negative:** Missing valuable conversation (lost opportunity)

**Strategy:** Prefer false negatives (better to miss some than annoy users with bad suggestions)

**Tuning Approach:**

1. **Start conservative**: Use thresholds from AC (>10 tools, >100 lines)
2. **Monitor user actions**: Track accepted vs declined suggestions
3. **Adjust thresholds**: If decline rate >70%, increase thresholds

**Future Enhancement (Not Story 1.18):**

- Machine learning: Train classifier on accepted/declined suggestions
- Project-specific thresholds: Higher threshold for projects with frequent small conversations
- User-specific learning: Adapt thresholds based on individual user's acceptance patterns

### Session-End Hook Performance

**Performance Requirement:**

Session-end hooks must complete quickly (<2s) to avoid blocking Claude Code shutdown.

**Optimization Strategies:**

1. **Database query optimization**:
   - Index on `timestamp` (already exists: idx_exchanges_timestamp)
   - Single query for last conversation: `SELECT * FROM exchanges ORDER BY timestamp DESC LIMIT 1`
   - Batch load exchanges for conversation: `SELECT * FROM exchanges WHERE id IN (...)`

2. **Heuristic analysis performance**:
   - All heuristics are O(n) where n = number of exchanges
   - Typical conversation: 10-50 exchanges → <10ms analysis time
   - Short-circuit: If heuristic 3 (user signal) found, skip remaining heuristics

3. **Non-blocking prompt**:
   - If terminal is non-interactive (TTY check), skip prompt (silent exit)
   - Async/await ensures CLI doesn't block if user takes time to respond

**Timeout Handling:**

```typescript
const PROMPT_TIMEOUT = 30000;  // 30 seconds

async function promptWithTimeout(message: string): Promise<boolean> {
  const timeoutPromise = new Promise<boolean>((resolve) => {
    setTimeout(() => resolve(false), PROMPT_TIMEOUT);
  });

  const promptPromise = confirm({ message });

  return Promise.race([promptPromise, timeoutPromise]);
}
```
