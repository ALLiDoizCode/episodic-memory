# Story 1.8: Hybrid Sync Workflow

**Status:** Done

**Epic:** 1 - Decentralized Cross-Device & Multi-Agent Memory

**Story Statement:**
**As a** user with AO/Arweave configured
**I want** `episodic-memory sync` to upload new conversations
**So that** my memory is backed up and accessible cross-device

## Acceptance Criteria

1. `sync` command detects backend from config (local or AO/Arweave)
2. Local-only mode: indexes to SQLite (current behavior, unchanged)
3. AO/Arweave mode: parses → uploads to Arweave → indexes to AO → caches to SQLite
4. Batch processing with concurrency (10 conversations in parallel)
5. Progress indicator shows upload status
6. Failures logged but don't stop sync (continue with next conversation)
7. Session-end hook continues working (`hooks/hooks.json` unchanged)

## Integration Verification

- IV1: Synced conversations searchable on different device (cross-device test)
- IV2: Local SQLite retains copy (offline access works)
- IV3: Existing local-only users unaffected (no config = local mode)

### Architecture Alignment

Story 1.8 implements the **Conversation Indexing Flow (Hybrid Backend)** workflow:

**Workflow Steps:**
1. **Session-End Hook** triggers `episodic-memory sync` command
2. **CLI** calls `backend.sync(options)` with selected backend
3. **Backend Selection:**
   - **Local mode:** Uses LocalSQLiteBackend (existing sync.ts behavior)
   - **AO/Arweave mode:** Uses AOArweaveBackend (new hybrid workflow)
4. **Hybrid Backend Sync (AOArweaveBackend.sync()):**
   - Parse conversation files with existing parser
   - Generate embeddings with existing embeddings generator
   - Upload conversations to Arweave (via permaweb-mcp)
   - Index metadata to AO process (via permaweb-mcp)
   - Cache to local SQLite with CacheManager
   - Batch process with concurrency control (10 parallel)
5. **Progress Reporting:** Show upload status and sync results

**Key Architectural Decisions:**
- **Backend abstraction:** sync() method is part of SearchBackend interface (Story 1.1)
- **Factory pattern:** createBackend(config) selects backend based on config.defaultBackend
- **Backward compatibility:** Local mode unchanged, AO mode is additive

**AOArweaveBackend.sync() Implementation:**
```typescript
// src/backend/ao-arweave.ts
async sync(options?: SyncOptions): Promise<SyncResult> {
  const result: SyncResult = {
    copied: 0,
    skipped: 0,
    indexed: 0,
    summarized: 0,
    errors: []
  };

  // 1. Scan for new/updated conversation files
  const sourceDir = path.join(os.homedir(), '.claude', 'projects');
  const files = await this.scanForNewConversations(sourceDir);

  // 2. Batch process with concurrency (AC 4)
  const concurrency = 10;
  for (let i = 0; i < files.length; i += concurrency) {
    const batch = files.slice(i, i + concurrency);

    await Promise.all(
      batch.map(async (file) => {
        try {
          // Parse conversation
          const exchanges = await parseConversation(file.path, file.project, file.path);

          for (const exchange of exchanges) {
            // Generate embedding
            const embedding = await generateExchangeEmbedding(
              exchange.userMessage,
              exchange.assistantMessage,
              exchange.toolCalls?.map(tc => tc.toolName)
            );

            // Upload to Arweave (AC 3)
            const txId = await this.arweaveClient.uploadConversation(file.path);

            // Index to AO (AC 3)
            await this.aoClient.indexToAO(this.config.aoProcessId, exchange, txId);

            // Cache to SQLite (AC 3)
            await this.cacheManager.updateCache([{
              ...exchange,
              arweave_tx: txId,
              last_cached: Date.now()
            }]);

            result.indexed++;
          }

          result.copied++;
        } catch (error) {
          // AC 6: Log failures but continue
          result.errors.push({
            file: file.path,
            error: error instanceof Error ? error.message : String(error)
          });
        }
      })
    );

    // AC 5: Progress indicator
    console.log(`Synced ${Math.min(i + concurrency, files.length)} / ${files.length} conversations...`);
  }

  return result;
}
```

**Sync Status Check (Before Upload):**
```typescript
async scanForNewConversations(sourceDir: string): Promise<ConversationFile[]> {
  const db = initDatabase();
  const files: ConversationFile[] = [];

  // Walk source directory
  const projects = fs.readdirSync(sourceDir);

  for (const project of projects) {
    const projectPath = path.join(sourceDir, project);
    const conversationFiles = fs.readdirSync(projectPath).filter(f => f.endsWith('.jsonl'));

    for (const file of conversationFiles) {
      const filePath = path.join(projectPath, file);
      const conversationId = this.extractConversationId(filePath);

      // Check sync_status table
      const syncStatus = db.prepare(`
        SELECT synced_to_ao, synced_to_arweave
        FROM sync_status
        WHERE conversation_id = ?
      `).get(conversationId);

      if (!syncStatus || !syncStatus.synced_to_ao || !syncStatus.synced_to_arweave) {
        files.push({ path: filePath, project, conversationId });
      }
    }
  }

  db.close();
  return files;
}
```

```typescript
// Good: Use async/await
async sync(options?: SyncOptions): Promise<SyncResult> {
  const files = await this.scanForNewConversations(sourceDir);
  const result = await this.processBatch(files, concurrency);
  return result;
}

// Bad: Never use raw Promises
sync(options?: SyncOptions): Promise<SyncResult> {
  return this.scanForNewConversations(sourceDir).then(files => {
    return this.processBatch(files, concurrency);
  });
}
```

## Technical Notes

**Batch Concurrency Strategy:**

[Source: architecture/coding-standards.md#concurrency-patterns]

Story 1.8 uses **concurrency = 10** for batch processing (AC 4):

**Rationale:**
- **I/O-bound operations:** Arweave uploads and AO indexing are network I/O
- **Parallel efficiency:** 10 concurrent uploads balance throughput and resource usage
- **Error isolation:** Each conversation processed independently (failure doesn't block others)

**Contrast with Sequential Processing:**
- Sequential (concurrency = 1): ~30s per conversation × 100 = 50 minutes
- Concurrent (concurrency = 10): ~30s per batch × 10 batches = 5 minutes

**Why 10?**
- Network connections: Most systems handle 10 concurrent HTTPS requests well
- Memory usage: 10 concurrent embeddings (~400KB each = 4MB total)
- Progress updates: Batches of 10 provide meaningful progress indicators

**Sync Status Table Usage:**

[Source: architecture/database-schema.md#sync_status-table]

The `sync_status` table prevents duplicate uploads:

**Before Sync:**
1. Query sync_status for each conversation file
2. If `synced_to_ao = 1` AND `synced_to_arweave = 1`, skip file
3. If either flag is 0 or row doesn't exist, include in sync batch

**After Successful Sync:**
1. INSERT OR REPLACE into sync_status
2. Set both flags to 1
3. Record arweave_tx, ao_indexed_at timestamp
4. Clear sync_error field

**On Sync Error:**
1. UPDATE sync_status with sync_error message
2. Set last_sync_attempt timestamp
3. Leave flags at 0 (will retry on next sync)

**Benefits:**
- Incremental sync (only new conversations uploaded)
- Idempotent (safe to run sync multiple times)
- Error tracking (debug failed uploads)

**Backward Compatibility Guarantee:**

[Source: epic-1#story-18-acceptance-criteria]

Story 1.8 maintains **full backward compatibility** with existing local-only users (AC 3, IV3):

**Scenarios:**
1. **User with no config file:**
   - configManager.loadConfig() creates default config (defaultBackend: 'local')
